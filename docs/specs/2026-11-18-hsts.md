# HSTS on swimtrends.dk

## Why
Security review of the www redirect (2026-11-18): no `Strict-Transport-Security`
header, so a visitor's first plain-http request can be intercepted before
CloudFront's http→https redirect.

## Decision
`Strict-Transport-Security: max-age=31536000; includeSubDomains` — no `preload`
(user's call: preload needs manual submission and takes months to undo).
- One year straight away, no ramp: http already only redirects to https and
  nothing is served over http, so if HTTPS broke the site is down either way.
- `includeSubDomains` is safe: DNS has only the apex and `www` (both on this
  distribution) plus ACM-validation and Google-verification records.

## Change
1. `swimtrends-app/swimtrends_app/swimtrends_web_stack.py`: a custom
   `cloudfront.ResponseHeadersPolicy` with only `strict_transport_security`
   (`override=True`), attached to the default behaviour. Not the managed
   SecurityHeadersPolicy: that also adds X-Frame-Options, Referrer-Policy etc.,
   which are out of scope here.
2. `swimtrends-app/cloudfront/viewer_request.js`: the www→apex 301 is generated by
   the function itself, and the docs don't say a response-headers policy covers
   function-generated responses, so the header is added on that response too.
   One value, shared: the CDK test checks the policy and the function test checks
   the 301 against the same expected string.

## Affected paths
- `swimtrends-app/swimtrends_app/swimtrends_web_stack.py`
- `swimtrends-app/cloudfront/viewer_request.js`
- `swimtrends-app/tests/unit/test_web_stack.py`
- Deploy: `SwimtrendsWebStack` only, with `-c alert_email`.

## Verification
- CDK assertions: policy with max-age 31536000, includeSubdomains, no preload,
  override; associated with the default behaviour. Function: 301 carries the header.
- `cdk diff`: new ResponseHeadersPolicy, distribution update, function code.
- Live `curl -sI`: header on `https://swimtrends.dk/`, a `/data/*.json`, a race
  page (SPA fallback) and the www 301; absent on `http://` responses.
